# Security policy

## Supported versions

There is no production release or supported deployment. Security review is best-effort against the latest `main` branch only.

| Version | Support |
|---|---|
| Latest `main` | Best-effort review |
| Tags, forks, deployments, or modified builds | Not supported |

## Reporting a vulnerability

Use GitHub Private Vulnerability Reporting through the repository's **Security** tab. The repository owner must enable that feature before public launch.

If the private reporting button is unavailable, do not publish exploit details, credentials, private data, or a working proof of concept in a public issue. Wait for a private channel exposed by the repository owner. GitHub platform abuse can be reported through GitHub's Report Abuse flow.

Include only sanitised synthetic reproduction material:

- affected commit or file;
- impact within this local prototype;
- minimal reproduction steps;
- suggested containment, if known.

Do not send real participant data, real locations, tokens, keys, browser profiles, or private logs.

## Scope boundary

Software issues involving local storage integrity, script injection, dependency compromise, unintended network transmission, or false deletion claims may be security issues.

Real-world route safety, opening hours, accessibility, NUS operations, field incidents, and user research ethics are outside this software security channel. The project is not authorised for those uses.

There is no response-time guarantee, bounty, embargo commitment, or promise of a fix.
